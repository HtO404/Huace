run_single_cycle — 每一轮在做什么？

🔁 脚本第 348-392 行

每一轮循环，会依次切换 3 个运营商：

🔁 第 N 轮循环开始
run_single_cycle(cycle_num)
⬇️
📡 切换 → 中国联通
switch_operator(联通, cycle_num)
⬇️
📝 写 CSV 结果
csv_reporter.write_result(...)
⬇️
📡 切换 → 中国电信
switch_operator(电信, cycle_num)
⬇️
📝 写 CSV 结果
csv_reporter.write_result(...)
⬇️
📡 切换 → 中国移动
switch_operator(移动, cycle_num)
⬇️
✅ 本轮完成

💡 每轮 = 3 次切换。如果循环 100 次，总共执行 300 次运营商切换操作。每次切换成功/失败都会写入 CSV 一行。

Bug #1：注释掉了等待逻辑

🚨 致命 Bug
# 脚本第 145-152 行（被注释掉了） # timeout_val = self.test_params['operator_switch_timeout'] # success, elapsed = self.wait_loading_dialog(timeout=timeout_val) # if not success: # return False, elapsed, "等待加载弹窗超时"

❌ 注释掉之后发生了什么

0.0 秒：点击"中国联通"按钮
0.1 秒：App 开始加载，弹出 loading 动画
0.2 秒：没等 loading 消失，直接去检查 network_level
0.3 秒：network_level 元素还不存在（因为还在加载）
结果：误判为失败！其实切换成功了，只是没等加载完

✅ 正确的流程应该是

0.0 秒：点击"中国联通"按钮
0.1 秒：App 开始加载，弹出 loading 动画
0.2~5.0 秒：等待 loading 消失
5.1 秒：检查 network_level 元素
结果：正确判断成功或失败
🚨 面试怎么说："我发现了脚本里一个 bug：switch_operator() 方法里，等待加载弹窗的代码被注释掉了。这导致点击运营商按钮后，没有等待 App 加载完成就去检查结果，容易误判为失败。修复方法是取消注释，或者加一个 time.sleep(3) 等待加载。"
🐛

Bug #2：卡死检测写了但没被调用

🚨 幽灵代码
# 脚本里写了这两个方法： def check_freeze(self) -> bool: # 第 268 行 """检测是否卡死""" ... def handle_freeze(self) -> bool: # 第 335 行 """处理卡死情况""" ... # 但是！run_single_cycle() 里从来没有调用过它们！
👻
check_freeze()
👻
handle_freeze()

这两个方法写了，但从来没有被调用过 → 幽灵代码

🚨 问题本质：脚本定义了 check_freeze() 和 handle_freeze()，但 run_single_cycle() 里从来没有调用过它们。这意味着：即使 App 卡死了，脚本也不会检测、不会处理，只会傻傻地等 200 秒。
⚠️ check_freeze() 本身也有问题：
elem.wait(timeout=200) — 等 200 毫秒（0.2 秒）
0.2 秒太短了！页面稍微渲染慢一点就算"卡死"。正常应该等 2-5 秒。
✅ 面试怎么说："我写了卡死检测和处理方法，但后来发现 run_single_cycle() 里没有调用它们。这是一个遗漏，应该在每次切换运营商前后调用 check_freeze()，检测到卡死后调用 handle_freeze() 重启 App。"

Bug #3：continue 跳过了后面的运营商

🚨 逻辑 Bug
# 脚本第 378-385 行 if success: self.success_count += 1 else: self.fail_count += 1 if self.test_params['operator_switch_timeout'] >= 100: self.logger.warning(f"切换失败: {remark}") continue # ← 这里！失败后跳到下一轮循环
🔁 第 N 轮开始
⬇️
📡 切换 → 中国联通
假设失败了
⬇️
🐛 continue 跳过了！
中国电信、中国移动都没测！
⬇️
🔁 直接进入第 N+1 轮
电信和移动被跳过了
🚨 后果：如果"中国联通"切换失败了，continue 会直接跳到下一轮循环，"中国电信"和"中国移动"都不会被测试。这意味着每轮循环不一定测 3 个运营商，可能只测了 1 个就跳过了。
⚠️ 修复建议：去掉 continue，让每个运营商都测完，不管成功失败都继续下一个。或者把 continue 改成 pass。

navigate_to_operator_page — 导航流程

这个方法负责从首页导航到运营商切换页面，经历了 5 个步骤：

self.device(resourceId=manual_flight_id).click()
等待 4 秒

Step 2：点击右侧空白区域（按坐标）

Step 3：点击【三】菜单按钮

Step 4：选择【4G】选项 + 向上滚动

08

知识汇总 — Q7-Q14 答案

📝 面试问答

Q7：check_freeze() 是怎么判断卡死的？有什么缺陷？

答案
它检查 network_level 元素在 200 毫秒内是否出现。200ms 太短了，页面稍微渲染慢一点就算卡死。应该改成 2-5 秒。而且这个方法根本没被调用过。

Q8：run_single_cycle() 检测到卡死会怎么处理？

答案
实际上它根本没有检测卡死！check_freeze() 和 handle_freeze() 写了但没被调用。这是脚本最大的 bug。

Q12：switch_operator() 里为什么注释掉等待逻辑？

答案
注释掉后，点击运营商按钮就立刻去检查结果，没等加载完成，导致误判失败。应该取消注释或加 sleep 等待。

Q14：continue 后后面的运营商还测不测？

答案
不测了。continue 会跳到 for 循环的下一次迭代，也就是下一轮循环。当前轮剩下的运营商都被跳过了。
