什么是单例模式？

💡 核心概念

单例模式（Singleton）的意思是：一个类只能创建一个实例。不管你 new 多少次，返回的都是同一个对象。

🎯 生活类比

想象一个公司只有一个 CEO。不管你怎么问"谁是 CEO"，答案永远是同一个人。你不能创建第二个 CEO，除非第一个卸任。

不管问几次，返回的都是同一个 CEO（同一个对象）

💡 面试怎么说："单例模式保证一个类只有一个实例，并提供全局访问点。常用于配置管理器、日志管理器、数据库连接池等场景。"

02

你的脚本里的单例 — ConfigManager

📝 utils.py 第 20-35 行

你的 ConfigManager 类用了单例模式。看代码：

class ConfigManager: """配置管理器""" _instance = None def __new__(cls, config_path: str = None): if cls._instance is None: cls._instance = super().__new__(cls) cls._instance._initialized = False return cls._instance def __init__(self, config_path: str = None): if self._initialized: return # 已经初始化过了，直接返回 self._initialized = True self.config = configparser.ConfigParser() self.config.read(config_path, encoding='utf-8')
🔑 两行关键代码：
__new__ 控制创建对象的过程（只创建一次）
__init__ 里的 if self._initialized: return 防止重复初始化
🔄 逐行拆解
第 1 次调用 ConfigManager()
_instance is None → 创建新对象 → _initialized = False → 进入 __init__ → 读取 config.ini → _initialized = True
第 2 次调用 ConfigManager()
_instance is NOT None → 直接返回已有对象 → 进入 __init__ → _initialized is True → 直接 return，不重复读取
第 3、4、5... 次调用
和第 2 次一样，永远返回同一个对象，永远不重复初始化
⚠️ 为什么需要单例？你的脚本里 ConfigManager 被多处调用。如果每次调用都重新读取 config.ini，会浪费 IO 操作，而且如果配置被中途修改，会导致不一致。单例保证配置只读一次，全局共享。

03

__new__ vs __init__ — 区别是什么？

💡 核心区别

__new__ — 创建对象

def __new__(cls): # 负责创建对象 # 返回一个实例 return super().__new__(cls)

类比：工厂生产手机。__new__ 决定要不要生产新手机，还是把库存里的给你。

__init__ — 初始化对象

def __init__(self): # 负责初始化 # 设置属性、读配置等 self.config = read_config()

类比：手机出厂后装系统、贴膜。__init__ 给对象设置初始值。

💡 执行顺序：先执行 __new__（创建对象），再执行 __init__（初始化）。
__new__ 是静态方法（虽然没写 @staticmethod），第一个参数是 cls（类本身）。
__init__ 是实例方法，第一个参数是 self（刚创建的对象）。
特性 __new__ __init__
作用 创建对象 初始化对象
参数 cls（类） self（实例）
返回值 对象实例 无（None）
调用时机 先调用 后调用
能否控制创建 ✅ 可以返回已有实例 ❌ 对象已经创建了

🎯 每个类只负责一件事：
ConfigManager → 只管读配置
LogManager → 只管写日志
CSVReporter → 只管写 CSV
ADBChecker → 只管检查 ADB

💡 为什么要这样设计？

❌ 不拆分的后果

所有代码写在一个文件里，2000+ 行
改日志逻辑可能影响配置读取
想复用 CSV 写入功能？只能复制粘贴
新人看不懂，不知道从哪里改起

✅ 拆分后的好处

每个类 100-200 行，清晰好读
改日志不影响配置，互不干扰
其他项目直接 import CSVReporter 复用
新人看类名就知道每个模块干嘛的
💡 面试怎么说："我把脚本拆成了 5 个类，每个类负责一个独立的功能模块。这样符合单一职责原则（SRP），修改一个模块不会影响其他模块，也方便其他项目复用。"

✅ 设计亮点：用 get_app_config() 等方法把配置按模块分组返回，调用方不需要知道配置文件的 section 结构，直接拿字典就行。
📝 LogManager — 日志管理器
class LogManager: def __init__(self, log_dir, log_filename): self.log_dir = log_dir self.log_filepath = os.path.join(log_dir, log_filename) self._ensure_dir() # 自动创建目录 def log(self, message, level="INFO"): timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S") log_entry = f"[{timestamp}] [{level}] {message}" with open(self.log_filepath, "a", encoding="utf-8") as f: f.write(log_entry + "\n") print(log_entry) # 同时打印到控制台 def info(self, message): self.log(message, "INFO") def error(self, message): self.log(message, "ERROR") def warning(self, message): self.log(message, "WARNING") def debug(self, message): self.log(message, "DEBUG")
✅ 设计亮点：日志同时写入文件和控制。调用方只需 logger.info("xxx")，不用管文件路径和格式。info/error/warning/debug 四个方法是对 log() 的封装，调用更方便。

扩展性分析 — 新增运营商要改几个地方？

🔍 面试官常问

① config.ini — 添加 operator_5g = com.xxx:id/btn_5g

💡 答案：改 3 个地方。不需要改测试逻辑代码，只需要改配置和列表。这说明你的脚本扩展性还不错——数据和逻辑分离了。
⚠️ 可以改进的地方：如果 OPERATORS 列表也放到 config.ini 里，那就只需要改 1 个地方（config.ini），扩展性更好。

Q9-Q11 面试答案

📝 面试问答

Q9：脚本用了单例模式，在哪？为什么需要？

答案
ConfigManager 用了单例。通过 __new__ 控制只创建一个实例，__init__ 里用 _initialized 防止重复初始化。这样配置只读一次，全局共享，避免重复 IO 操作。

Q10：拆成好几个类，好在哪？有什么可以改进的？

答案
每个类负责一个功能，符合单一职责原则。改日志不影响配置，方便复用。改进点：可以把 OPERATORS 列表也放到 config.ini，进一步分离数据和逻辑。

Q11：新增一个 5G 运营商，需要改几个地方？扩展性好吗？

答案
改 3 个地方：config.ini 加配置、get_ui_elements 加映射、OPERATORS 列表加一项。扩展性还行，数据和逻辑分离了。如果把 OPERATORS 也放到配置文件，就只需要改 1 个地方。
