# Superpowers Verification — 证据先行原则

## 核心准则

**声称工作完成前必须运行验证命令。未运行验证就声称成功 = 说谎，不是效率。** 在 `run_command` 跑完并读了输出之前，不要说"完成"。

## 验证流程

```
在声称任何状态之前：

1. 识别：哪个命令能证明这个说法？
2. 运行：用 run_command 执行完整命令
3. 读取：读完整输出，检查退出码
4. 验证：输出是否证实了说法？
   - 如果否：给出实际状态 + 证据
   - 如果是：给出说法 + 证据
5. 只有这时：才能做出声称

跳过任何步骤 = 说谎，不是验证
```

## 常见验证要求

| 声称 | 需要 | 不够 |
|------|------|------|
| 测试通过 | `run_command` 测试输出：0 failures | "之前运行过"、"应该能过" |
| Linter 干净 | `run_command` linter 输出：0 errors | 部分检查、推测 |
| 构建成功 | `run_command` 构建：exit 0 | Linter 通过 |
| Bug 修复 | `run_command` 原始症状测试：通过 | "代码改了" |
| 需求满足 | 逐项检查清单 | "测试通过了" |

## 红绿验证循环

```
✅ 写测试 → run 测试（通过）→ 回滚修复 → run（必须失败）→ 恢复 → run（通过）
❌ "我写了回归测试"（没有红绿验证）
```

## 禁止的措辞

以下措辞出现说明还没有验证：
- 使用 **"应该"、"大概"、"看起来"**
- 表达满意之前：**"很好！"、"完美！"、"完成了！"** 等
- 即将 commit/push 但没有验证
- **信任 agent 的成功报告**（不一定验证了）
- **依赖之前的测试结果**（代码改了，要重新跑）

## 验证检查表

用 `todo_write` 创建检查表：

- [ ] 用 `run_command` 运行了完整的测试命令
- [ ] 读取了完整输出
- [ ] 确认 0 failures / exit 0
- [ ] 其他相关测试仍然通过
- [ ] 报告包含实际证据（命令 + 输出摘要）

## Reasonix Code 工具映射

| 验证动作 | 工具 |
|---------|------|
| 运行测试 | `run_command` |
| 读输出 | `run_command` 返回结果 |
| 检查构建 | `run_command` |
| 追踪验证清单 | `todo_write` |
| 看代码变更 | `run_command("git diff")` |

## 常见违规模式

1. **"之前跑过了"** — 代码改了，之前的验证作废
2. **"应该没问题"** — 没跑就是没验证
3. **"看起来对了"** — 看起来对 ≠ 跑起来对
4. **"子 agent 说完成了"** — 子 agent 报告不是验证，要亲自跑命令确认
