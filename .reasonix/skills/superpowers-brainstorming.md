# Superpowers Brainstorming — 想法到设计

## 核心准则

**在创造性工作之前，通过协作对话将想法转化为完整的设计和规格说明。**

**硬性门槛：** 在调用任何实现工具、写任何代码之前，必须先展示设计并获得主人批准。无论感知到的复杂度如何，每个项目都要走这个流程。

"简单"项目正是未审视假设造成最多浪费的地方。设计可以很短，但必须展示并获得批准。

## 流程检查表

### 1. 探索项目上下文

用 Reasonix Code 工具做初始化探索：

- `directory_tree` — 了解项目结构
- `search_files` / `search_content` — 找相关文件
- `read_file` — 读关键文件
- `run_command` — git log 看最近变更

如果项目有 `explore` 内置 subagent 技能，也可以用它做宽泛调查。

### 2. 提出澄清问题

- 一次只问一个问题
- 优先用多选问题（配合 `ask_choice`）
- 理解：目的、约束、成功标准
- 如果请求描述多个独立子系统（"构建有聊天、文件存储、计费的平台"），立即标记并建议分解

### 3. 提出 2-3 种方案

- 每个方案带权衡分析
- 说明推荐方案和理由
- 用 `ask_choice` 让主人选择，或用 `submit_plan` 展示完整设计

### 4. 展示设计

- 按复杂度缩放：简单的几句话，复杂的 200-300 字
- 每部分后问"这样对吗？"
- 覆盖：架构、组件、数据流、错误处理、测试

### 5. 写设计文档

将经验证的设计保存到 `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`

### 6. 规格自审

检查：
- **占位符扫描：** 有 "TBD"、"TODO" 吗？
- **内部一致性：** 各部分矛盾吗？
- **范围检查：** 够聚焦吗？需要分解吗？
- **模糊检查：** 任何需求能有两种解释吗？

### 7. 主人审查书面规格

> "规格已写完并 commit 到 `<path>`。请审查。"

等主人回复。通过后才进入下一步。

### 8. 过渡到实现

调用 `superpowers-writing-plans` 技能创建详细实现计划。

## Reasonix Code 工具映射

| 阶段 | 使用工具 |
|------|---------|
| 探索上下文 | `directory_tree`, `search_content`, `search_files`, `read_file`, `run_command`, `explore` subagent |
| 提问题 | `ask_choice`（多选），或直接提问 |
| 展示方案 | `ask_choice` + 文字分析，或 `submit_plan` |
| 展示设计 | 文字描述，用 `submit_plan` 结构化呈现 |
| 写文档 | `write_file` |
| 审查 | 文字自我审查 + 主人确认 |

## 关键原则

- **一次一个问题** — 不要用多个问题压垮主人
- **多选优先** — 比开放问题更容易回答
- **YAGNI 彻底** — 从所有设计中移除不必要功能
- **探索替代方案** — 在确定之前总是提出 2-3 个方案
- **增量验证** — 展示设计，获得批准后再继续
